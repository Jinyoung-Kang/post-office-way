## 2. 진행 순서와 묶음

이번 범위는 **1장 전부**입니다(결정 대기 3건 제외). 우선순위 순서로, 한 주제씩 커밋합니다.

1. **데이터·보안 (백엔드)**: D1 → D2 → D3 → D4 → D5 → D6 → D7 → D8 → D9(구조: 실행 기록 컨텍스트 관리자 — 리팩터링 커밋과 버그 커밋을 나눔) → D11 → S1 → S3 → S4 → S5

3. **화면** (별도 작업 트리에서 병렬로, 끝나면 이 브랜치로 가져옴): S2 → B3(순수 함수 추출 → 버그) → W1~W7, B2 의 화면 상태 표시

5. **문서**: O5, README·CHANGELOG·ADR(013·023·024 갱신)·docs/README·benchmarks·quality

검증:
- 커밋마다 `make test` + ruff(백엔드), `tsc`·`eslint`·`vitest`(웹)를 돌립니다. 웹 빌드는 웹 커밋 묶음마다 돌립니다.
- 끝난 뒤 api·web 만 띄워(워커 제외 — 외부 API 호출 방지) 다음을 확인합니다.
  - `make bench` 로 같은 조건 전후를 비교합니다.
  - `scripts/qa` 의 `requests_check`·`failures`·`fuzz` 를 돌립니다.
  - 지도 화면은 실제 브라우저로 확인합니다.
