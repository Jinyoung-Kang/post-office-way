# 벤치마크 기록

`make bench` — 측정 동안만 속도 제한을 끄고(api 재기동), 같은 도커 네트워크의 collector 컨테이너에서 경로마다 동시 16개로
200회(What-if 50회) 요청합니다. uvicorn 워커 2, PostgreSQL 16 + PostGIS 3.6, Redis 7, Apple Silicon 로컬, 전국 실데이터.
끝에 `pg_stat_statements` 누적 시간 상위 SQL 을 함께 출력합니다.

## 코드 리뷰 개선 (2026-10-09)

도커 스택의 다른 부하에 따라 전체가 1.4배쯤 오르내립니다 — 리뷰 계획(10-08)에서 지역 상세 106/760ms 로 보였던 것이 그 예.

## 2차 코드 리뷰 (2026-10-15)

측정한 곳은 경로 비용이 바뀌는 수정뿐입니다(추측으로 바꾼 성능 수정은 없음). 환경은 로컬 Docker Desktop(arm64)이고, 같은 컴퓨터에 다른 도커 스택이 함께 돌았습니다.

| 항목 | 전 → 후 | 조건·판단 |
|---|---|---|
| 은행 지점 최근접 동률 처리(B8, [ADR-027](adr/ADR-027-nearest-tie-break.md)) | 4,138 → 4,397ms (+6%) | 집계구 105,947곳 · 은행 지점 5,425곳, 같은 세션에서 번갈아 3회 중앙값. 대안 '매번 다시 찾기' 5,353ms(+29%), 'KNN 정렬 키에 id' 120초 초과 → 채택 안 함 |
| 방문 여건 캐시 버전 질의(B1) | 2.0~3.7 → 1.7~4.9ms | 같은 질의 6회(읽기 전용) — 차이 없음 |
| `/visit/conditions` 서버 처리 시간 | p50 5.5 → 5.5ms, 0.5 → 0.5ms | 수정 전·뒤 이미지를 번갈아 띄워 순차 200회씩 2쌍(Server-Timing) — 차이 없음 |
| `make bench`(동시 16·경로당 200회) | 판정 못 함 | 수정 전·뒤를 번갈아 2회씩 쟀지만 같은 판 안에서도 health p50 이 46~98ms 로 흔들려(다른 스택 부하) 비교하지 않음. 원자료는 세션 기록(PROGRESS.md) |
| 지도 `simplify` 단계(S3) | 501 → 9단계 | 성능 수정이 아니라 보안(DB 시간 증폭 차단). 기본값 아닌 단계는 요청당 시군구 252곳 단순화 1.3초·3MB(측정) |
