# ADR-016 지도 표시 방식 — 늘 보이는 정보, 확실한 첫 그리기

- 상태: 채택 (2026-09-25)

## 맥락
- 사용자 환경(고해상도·일부 브라우저)에서 단계구분도 폴리곤이 **마우스를 올려야** 색이 보였다. 폴리곤을 지도에 먼저 붙이고
  `setBounds` 로 화면을 옮기면, 이동 뒤 벡터 층을 다시 그리지 않는 경우가 있었다(마우스 오버 = 그 영역 다시 그리기).
- 정보도 마우스 오버 말풍선에만 있어 터치 기기에서는 볼 수 없고, 한눈에 핵심 지역이 보이지 않았다.
- 방문 여건 지도(높이 560px)는 카카오 확대 단계가 2배씩이라 전국이 한 단계 안에 안 들어가 한 단계 더 멀리(작게) 보였다.

## 결정
1. **맞추고 → 붙이고 → 칠하기**: 폴리곤을 지도에 붙이지 않은 채 만든 뒤 `setBounds`, 이동이 끝난 `idle`(없으면 400ms)에서 한꺼번에
   `setMap` + 칠하기 + 다음 프레임에 한 번 더 칠하기. 컨테이너 크기가 바뀌면(`ResizeObserver`) `relayout` 후 다시 칠하고,
   탭이 다시 보일 때(`visibilitychange`)도 다시 칠한다.
2. **늘 보이는 라벨**: 지도마다 핵심 지역을 대표점(`ST_PointOnSurface`, GeoJSON 속성 lat·lon)에 알약 라벨로 표시 —
   지도: 선택 지표의 취약 상위 8곳(순위·값, 끄기 가능) · 방문 여건: 먼저 살펴볼 지역(원인) · 배치 제안: 우체국이 가장 먼 5곳 ·
   What-if: 거리가 가장 많이 늘어나는 5곳. 화면 좌표로 **겹침을 판정해 우선순위가 낮은 라벨은 숨기고**, 확대하면 다시 보인다.
3. **누르면 고정**: 지역을 누르면(터치 포함) 말풍선이 고정되고, 빈 곳이나 같은 지역을 다시 누르면 닫힌다
   (카카오는 도형 클릭 뒤 지도 클릭도 보내므로 300ms 안의 지도 클릭은 무시). 지도 화면은 누르면 오른쪽 상세 카드.
4. 방문 여건 지도 높이를 700px 로 — 전국(위도 5.5°)이 한 단계 가까운 수준(13)에 들어감.

## 대안
- 폴리곤을 캔버스·SVG 오버레이로 직접 그리기: 확대·이동 동기화를 직접 해야 해 복잡도 대비 이득이 작음.
- MapLibre GL 로 교체: 벡터·라벨·호버 상태가 강력하지만 한국 지도 타일(카카오)을 쓸 수 없어 배경 지도 품질·약관 부담.

## 보완 (2026-10-15) — 넓은 창에서 지도 끝이 잘려 보이던 것
- **증상**: 2,500px 넘는 창의 첫 화면에서 지도 왼쪽·오른쪽·아래에 하늘색 띠와 흰 바탕이 보이고 중국·일본 땅이 직선으로 잘렸다.
  `setBounds` 가 전국을 여백 안에 넣으려고 단계 13 을 골랐는데, 카카오 타일에 그림이 있는 범위가 단계 13 에서 가로 약 1,934px 뿐이었다.
- **원인**: 카카오 기본 지도 타일은 WCONGNAMUL 좌표의 고정된 사각형(대략 X −1.88M~3.08M, Y −0.55M~3.13M) 안에만 그림이 있다.
  그 밖은 타일 격자 안이면 바다색 타일, 격자 밖이면 흰 이미지다. 경계는 브라우저에서 단계 12·13·14 마다 재었고 셋이 같았다.
- **결정**(`web/lib/mapView.ts` 계산, `web/lib/kakao.ts` 의 `limitView`·`keepInside`·`maskOutside` 가 SDK 에 적용)
  1. **축소 한계를 창 크기에 맞춤**: 화면이 범위 안에 드는 가장 먼 단계까지만 줄인다(`setMaxLevel`). 지도를 만들 때와 크기가 바뀔 때 다시 정한다.
     다만 그 단계에서 전국이 다 들어가지 않으면, 전국이 들어가는 단계까지는 허용한다. 전국 보기가 먼저다.
     결과: 2548×1205 는 12(전에는 13), 1024×716 은 13(전에는 14 까지 줄일 수 있었음), 2560×1080 은 13.
  2. **이동 범위**: 끌거나 확대·축소한 뒤(`idle`) 화면이 범위를 넘으면 부드럽게 안으로 되돌린다. 화면이 범위보다 넓은 축은 범위 가운데에 둔다.
  3. **범위 밖 덮개**: 1 의 예외(넓고 낮은 창)처럼 범위를 넘을 수밖에 없을 때를 위해 둔다. 범위 밖을 타일과 같은 바다색(`#a3d6eb`, 타일
     팔레트에서 읽음)의 `Polygon` 으로 덮는다. 범위 안쪽 16km 는 8겹으로 점점 옅게 칠해, 잘린 땅이 바다로 흐려진다. 공개 API 만 쓴다.
- **대안**
  - 흰 타일(`…/mapjsapi/images/white.png`)을 CSS 로 숨기고 바탕을 바다색으로 칠하기: SDK 내부 이미지 경로에 기대고, 잘린 땅은 그대로 보인다.
  - 넓고 낮은 창에서도 단계 12 고집: 전국이 위아래로 잘린다(2560×1080 에서 약 160px — 제주·강원 북부, 취약 지역 라벨 포함).
- **감수한 것**
  - 범위 상수는 측정값(안쪽으로 2km 여유)이다. 카카오가 타일 범위나 바다색을 바꾸면 다시 재야 한다(재는 방법은 위 원인 항목).
  - 넓고 낮은 창에서는 가장자리가 흐려지는 띠가 보인다.
  - 범위 끝 근처(중국·일본 해안)까지 끌면 땅이 흐려진다.
- **말풍선 위치**(`lib/mapTip.placeTip`): 기본은 가리킨 점 위 가운데다. 지도 끝이나 떠 있는 패널에 가리면 좌우는 안쪽으로 밀고,
  위가 모자라면 점 아래로 둔다. 패널 영역은 화면 맞춤에 쓰는 `padding` 을 그대로 쓴다. 오버레이 기준점을 왼쪽 위(0, 0)로 두고 내용 상자를 옮긴다.
  SDK 가 `setMap` 때 바로 DOM 에 넣으므로 크기를 재고 옮기는 일이 한 프레임 안에 끝나 깜박이지 않는다.
- **크기가 바뀔 때 중심 유지**(`relayoutKeepingCenter`): SDK 의 `relayout` 은 화면 왼쪽 위를 고정한다(400×300 → 900×650 에서
  원래 중심이 새 가운데가 아니라 (201, 149)에 남음). `relayout` 전에 읽은 중심은 옛 크기 기준으로 맞으므로 `relayout` 뒤에 다시 넣는다.
  SDK 는 창 `resize` 때 스스로 `relayout` 하지 않으며, 앱의 `ResizeObserver` 에서만 부른다(브라우저에서 확인).
- **컨테이너 스크롤 막기**(`pinContainer`): 지도를 만든 직후 SDK 가 붙인 `overflow: hidden` 을 `clip` 으로 바꾼다.
  `hidden` 상자는 `scrollIntoView`(스크립트·페이지 찾기·보조 기술)로 밀려, 타일·도형과 조작 단추가 어긋난 채 빈 띠가 생긴다.
  `clip` 은 스크롤 상자가 아니라 밀리지 않는다. Next 기본 대상 브라우저(Chrome 111·Safari 16.4·Firefox 111)는 모두 지원하고,
  SDK 의 `relayout` 도 이 값을 되돌리지 않는다(브라우저에서 확인).
