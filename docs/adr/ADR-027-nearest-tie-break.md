# ADR-027 같은 좌표 지점의 최근접 동률은 id 로 — 후보를 넉넉히 받아 정렬, 드물면 다시 찾기

- 상태: 채택 (2026-10-15, 2차 리뷰 B8)

## 맥락
- 집계구마다 '가장 가까운 은행 지점'(`calc_oa_bank.b1`)을 KNN(`ORDER BY geom <-> rep LIMIT 2`)으로 고르고, 거리로만 정렬했다.
- 같은 건물에 있는 지점들처럼 거리가 같으면 KNN 이 돌려주는 순서는 정해지지 않는다. 그 순서는 표의 물리 순서를 따르고, 물리 순서는
  수집 때 `last_seen` UPDATE 로 바뀐다. 그래서 같은 입력이어도 이용 주민·AGED_20 사유·등급·순위가 묶음 안의 다른 지점으로 옮겨 갈 수 있었다(NFR-03 재현성).
- 실데이터: 같은 좌표 묶음 59개(최대 4곳). 그 지점을 b1 으로 둔 집계구는 478곳(24만 명)이다.
- 1차 R11 은 02·06(우체국)에 '후보를 하나 더 받아 (거리, id) 정렬'을 넣었지만 이 문장에는 빠졌다.

## 결정
- 후보 5곳을 받아 (거리, place_id) 로 정렬하고 1순위를 쓴다.
- 5곳이 모두 같은 거리이면(같은 좌표 5곳 이상) 그 거리 안(`ST_DWithin`)에서 id 가 가장 작은 지점을 다시 찾는다. 이 경우만 질의가 한 번 더 돈다.

## 검토한 대안 (같은 세션에서 번갈아 3회 중앙값, 집계구 105,947곳 · 은행 지점 5,425곳)
| 방식 | 시간 | 판단 |
|---|---|---|
| 지금(LIMIT 2, 거리만) | 4,138ms | 동률 비결정 |
| **후보 5곳 + (거리, id) 정렬 (채택)** | 4,397ms (+6%) | 같은 좌표 4곳까지 결정적, 그 이상은 다시 찾기로 |
| 거리 2개는 KNN, b1 은 매번 d1 안에서 다시 찾기 | 5,353ms (+29%) | 늘 결정적이지만 느림 |
| KNN 정렬 키에 id 추가(`ORDER BY <->, place_id`) | 120초 제한 초과 | 인덱스 KNN 을 못 써 집계구마다 전체 정렬 — 쓰지 않음 |

결과 차이: b1 이 바뀌는 집계구는 310곳으로 모두 같은 좌표 묶음에 속하고, 거리(d1·d2)는 바뀌지 않는다.
우체국(02·06)은 금융 가능 시설 가운데 같은 좌표 묶음이 0건이라 지금 방식(후보 +1)을 그대로 둔다.

## 감수한 단점
- 계산의 은행 지점 영향 단계가 약 6% 느려진다(전체 계산 약 40초 중 0.3초 안팎).
- 처음 계산할 때 같은 좌표 묶음의 이용 주민이 id 가 가장 작은 지점으로 모인다(의도한 변화).
