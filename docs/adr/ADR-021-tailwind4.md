# ADR-021 Tailwind CSS 4 전환 — 빌드 도구 취약점 해소, 화면이 바뀌지 않았음을 픽셀로 확인

- 상태: 채택 (2026-10-08, 사용자 결정)

## 맥락
- 2026-10 공개된 npm 취약점 중 높음 7건이 Tailwind CSS 3 의 빌드 도구 사슬(braces → micromatch·chokidar·fast-glob)에 있었다.
  braces 에 고친 판이 없어 Tailwind 4(메이저)로 올려야만 없어진다. 이 도구들은 빌드 때만 돌고 실행 이미지에는 들어가지 않는다.
- 선택지: (A) CI 차단 기준을 실행용 의존성으로만 좁히고 전환은 나중에 (B) 지금 전환 (C) 그대로 둠 → 사용자가 **(B)** 를 골랐다.

## 결정
1. 공식 업그레이드 도구(`npx @tailwindcss/upgrade`)로 의존성·템플릿 클래스 이름(`shadow`→`shadow-sm`, `!` 위치 등)을 바꾸고,
   **스타일시트는 도구 결과를 쓰지 않고 손으로 최소한만** 바꿨다 — 도구는 `.card`·`.gnav` 같은 컴포넌트 클래스를 모두 `@utility` 로
   바꾸면서 `@utility on { .gnav &a.item … }` 처럼 어색한 중첩과 Tailwind 의 `group` 표식과 겹치는 `@utility group` 을 만들었다.
   - `@tailwind …` 세 줄 → `@import "tailwindcss"`, `tailwind.config.js` 테마 → `@theme`(색 6개·최대 폭 2개).
   - v4 기본값 변화(테두리 색 currentColor, 버튼 커서 default, 입력 안내 글자 색)를 v3 와 같게 하는 호환 규칙을 `@layer base` 에.
   - 컴포넌트 클래스는 그대로 `@layer components` — 변형(`hover:card` 등)으로 쓰지 않아 `@utility` 가 필요 없다.
2. **autoprefixer 제거**(v4 가 벤더 접두사를 직접 처리), 버전은 정확히 고정(`4.3.3`). 같은 김에 Next.js 15.5.26 → **15.5.27**
   (자체 호스팅 SSG/ISR 캐시 오염 취약점, 같은 메이저 패치). → `npm audit` **0건**(개발용 포함).
3. **화면이 바뀌지 않았는지 픽셀로 확인** — 전환 전후 13개 화면 × 데스크톱·모바일 전체 페이지 26장을 같은 조건으로 찍어 비교.

## 결과 — 비교에서 찾은 것
- **cascade layer 함정**: v4 는 브라우저의 cascade layer 를 쓴다. 레이어 밖에 있던 `a { color: var(--link) }` 가 명시도와 상관없이
  `@layer components` 의 `.gnav a.item`·유틸리티 `text-ink` 를 이겨 **메뉴와 링크 배지가 모두 파란 링크 색**이 됐다.
  요소 기본 스타일(`html`·`body`·`a`·`::selection`)을 `@layer base` 로 옮겨 해결 → 23개 화면은 0px 차이.
- 남은 차이 3곳은 의도된 변화: 지도 패널 안내 글이 선택 상자에 붙음(v3 에서는 `space-y` 가 `-mt-3` 을 덮어써 적용되지 않던 것이
  v4 의 `space-y` 선택자 변경으로 적용됨), What-if 빈 안내 글의 줄바꿈 3px, 출력 시각 같은 시간 표시.
- 이어서 모바일 점검을 고치다(아래) 화면 3곳의 가로 넘침을 함께 고쳤다.

## 덧붙여 찾은 모바일 가로 넘침 (전환과 무관, 이전부터 있던 문제)
- 품질 점검의 '모바일 넘침' 검사가 `scrollWidth - innerWidth` 를 썼는데, 모바일 에뮬레이션에서는 내용이 넓으면 브라우저가 화면을
  축소해 `innerWidth` 도 같이 커져 늘 0 이었다. 실제 화면 폭(375px)과 비교하도록 고치자 넘침이 드러났다.
  - 생활 거점: 표 머리글의 화면 낭독용 글자(`sr-only`, absolute)가 가로 스크롤 상자에 잘리지 않고 페이지 폭을 630px 로 늘림 → `.tbl` 을 `relative` 로.
  - 은행 지점·데이터·운영: 모바일의 한 열 그리드가 `auto` 라 넓은 표에 맞춰 늘어남 → 반응형 그리드마다 `grid-cols-1`(minmax(0,1fr)).
  - 방문 여건·지역 보고서: 세그먼트 버튼(줄바꿈 없음)이 화면 밖으로 → `.seg` 를 화면 폭 안에서 가로로 밀어 보게.
- 은행 지점 화면의 CLS(0.07~0.12)도 같은 원인(그리드가 표 폭으로 늘었다 줄어듦)이었다.
