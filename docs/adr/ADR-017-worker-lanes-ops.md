# ADR-017 워커 차선(short·long)·생존 신호, 생존/준비 확인 분리, 백업·복원

- 상태: 채택 (2026-09-26)

## 맥락
- 워커가 작업을 **한 번에 하나씩** 실행했다. 도로 거리(`road`, 약 25분)·영업점(`banks`, 약 10분)이 도는 동안
  3시간마다 들어오는 기상청 예보·미세먼지 예보 작업이 그 뒤에 줄을 섰다(head-of-line blocking) — "오늘 방문 여건"이 오래된 예보로 남는다.
- 워커가 살아 있는지 알 방법이 없었다. 작업 행의 하트비트는 **실행 중일 때만** 갱신되므로, 워커가 멈추면
  대기 작업이 쌓이는 것을 보고서야 알 수 있었다. compose 에도 워커 healthcheck 가 없었다.
- `/health` 하나가 DB·Redis·스키마·큐를 모두 확인해, "프로세스가 살아 있나"와 "요청을 받을 준비가 됐나"가 섞여 있었다.
- DB 백업·복원 절차가 없었다(수집에 약 1시간, 외부 API 호출 한도 소모).

## 결정
1. **작업 차선** — 작업 종류마다 `long` 여부(`JobSpec.long`)를 두고, 워커는 차선별 스레드를 띄운다.
   - `short`: 예보·대기·공휴일·약국/병의원·계산 등 몇 분 안에 끝나는 작업. `long`: 집계구·영업점·도로 거리·좌표 검증.
   - 가져가기는 `claim(worker, kinds)` — `kind = ANY(:kinds)` 조건을 더한 같은 `FOR UPDATE SKIP LOCKED` 쿼리. 차선끼리 겹치지 않으므로 중복 실행 없음.
   - 스케줄 넣기·끊긴 작업 정리(`reap`)는 `short` 차선 하나만 맡는다(차선 수만큼 중복 실행하지 않게).
   - `atlas worker --lane short|long` 로 차선을 다른 컨테이너로 나눠 띄울 수도 있다(기본 `all` = 한 프로세스 두 스레드).
   - 대안: 워커 프로세스 여러 개(작업 수만큼 동시 실행 — 외부 API 한도·DB 부하 제어가 어려움), 우선순위 열(긴 작업이 이미 실행 중이면 소용없음).
2. **워커 생존 신호 `ops.worker`** (V16) — 차선 스레드마다 `(worker, lane, started_at, last_seen, job_id)` 를 30초 간격(대기 중 LISTEN 타임아웃, 실행 중 하트비트)으로 갱신.
   정상 종료 때 행 삭제, 하루 넘게 끊긴 행은 `reap` 가 정리. API(`atlas_api`)는 **읽기만**.
   - `GET /health` 의 `workers` — 최근 2분 안에 신호를 보낸 차선, 실행 중 작업 번호. 데이터·운영 화면 배지 "워커 동작 중 / 짧은 작업만 / 멈춤".
   - compose `worker` healthcheck: `atlas worker-check` — 이 컨테이너의 두 차선이 90초 안에 신호를 보냈는지. 한 차선 스레드만 죽어도 unhealthy.
3. **생존/준비 확인 분리** — `GET /health/live` 는 DB 를 보지 않는 프로세스 생존 확인(재시작 판단용),
   `GET /health` 는 준비 상태(DB·Redis·스키마·작업 큐·워커). compose 의 api healthcheck·`web` 의 `depends_on` 은 준비 상태를 쓴다.
   워커는 API 와 별도 서비스라 준비 상태의 `status` 에는 넣지 않고 정보로만 보여 준다.
4. **백업·복원** — `make backup`: `pg_dump -Fc`(압축) → `backups/`(git 제외), `LITE=1` 이면 원본 응답(`raw.*`) 데이터를 빼 약 1/3 크기.
   `make restore FILE=…`: 확인 → api·worker·web 정지 → DB 재생성 → `pg_restore --exit-on-error` → 기동(migrate 가 역할 비밀번호 재설정).
   역할(`atlas_api`)은 클러스터 전역이라 덤프에 없고, 권한(GRANT)은 덤프에 있다.

## 검증
- `test_long_job_does_not_block_short_lane`: 긴 작업이 실행 중인 동안 나중에 넣은 짧은 작업이 5초 안에 끝나고,
  `workers()` 에 두 차선이 보이며 long 차선에 실행 중 작업 번호가 있고, 종료 뒤 생존 신호 행이 사라짐.
- 실제 스택: 두 차선 기동 로그, `docker compose ps` 에서 worker `healthy`, `/health` 의 `workers` 2개.
- 백업 복원: 경량 백업(113MB, 14초)을 임시 DB 로 복원 → 지역 3,811 · 지표 547,289 · 시설 이력 56,656 · 마이그레이션 16 ·
  `atlas_api` 권한 34건이 운영 DB 와 같음(원본 응답만 제외) 확인 뒤 임시 DB 삭제.

## 남는 점
- 한 차선 안에서는 여전히 한 번에 하나다(예: 도로 거리와 영업점 수집은 순서대로). 외부 API 한도를 생각하면 의도한 제한이다.
- 백업은 수동이다. 운영 배포 시에는 예약 백업과 보관 정책(예: 7일·4주)을 두고 복원 연습을 정기적으로 한다.
