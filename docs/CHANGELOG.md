# 변경 이력

## 2026-10-15 — 넓은 창에서 지도 끝이 잘려 보이던 것

결정과 측정은 [ADR-016](adr/ADR-016-map-display.md) 보완.

- 2,500px 넘는 창의 첫 화면에서 지도 가장자리에 하늘색 띠·흰 바탕이 보이고 이웃 나라 땅이 직선으로 잘렸습니다.
  카카오 타일에 그림이 있는 범위가 단계 13 에서 가로 약 1,934px 뿐인데 그보다 넓은 화면을 그 단계로 맞췄기 때문입니다.
- 축소 한계를 창 크기에 맞춥니다. 화면이 범위 안에 드는 단계까지만 줄이고, 그 단계에서 전국이 다 들어가지 않을 때만 한 단계 더 허용합니다.
  끌거나 확대·축소한 뒤 범위를 넘으면 안으로 되돌립니다.
- 그래도 범위를 넘는 넓고 낮은 창(예: 2560×1080)을 위해, 범위 밖은 바다색으로 덮고 가장자리는 바다로 흐려지게 했습니다.
- 확인한 창 크기: 2548×1255·1920×1080·2000×1000·2560×1080·1024×768·375×812(지도·방문 여건). 흰 타일 0개, 전국이 다 보입니다.
- 지도 컨테이너가 스크롤되지 않게 했습니다. 카카오 SDK 가 붙이는 `overflow: hidden` 을 `clip` 으로 바꿨습니다.
  `overflow: hidden` 상자는 사용자가 직접 스크롤할 수는 없어도 `scrollIntoView` 로는 밀립니다(브라우저 자동화가 확대 단추를 누를 때 493px).
  그러면 지도 오른쪽 절반이 비고 확대 단추가 가운데로 옮겨졌습니다. 실제 Tab·끌기로는 재현되지 않았고, 미리 막아 두는 수정입니다.
  화면 밖으로 삐져나온 말풍선 글자를 페이지 찾기로 찾는 경우를 같은 호출로 흉내 내 보니, 이제 아무것도 밀리지 않습니다.
- 지도 가장자리에서 말풍선이 지도 밖으로 나가 끝 글자가 잘리던 것을 고쳤습니다(예: 오른쪽 끝 거창군 '· 83위/252').
  기본은 가리킨 점 위 가운데입니다. 지도 끝이나 떠 있는 패널에 가리면 좌우는 안쪽으로 밀고, 위가 모자라면 점 아래로 내립니다.
  마우스를 올릴 때와 누르면 고정될 때 모두 적용되고, 1024px 지도·왼쪽 패널 옆·위쪽 끝·휴대폰 지도에서 확인했습니다.
- 지도를 띄운 뒤 창 크기가 바뀌면 전국이 한쪽으로 밀리던 것을 고쳤습니다. 카카오 SDK 의 `relayout` 은 화면 왼쪽 위를 고정해,
  창을 키우면 원래 가운데가 옛 가운데 자리에 남았습니다. 이제 `relayout` 전의 중심을 다시 가운데로 둡니다.
  1100×800 → 1400×900 → 900×700 에서 전국 중심의 위치(지도 가운데 기준)가 그대로인 것을 확인했습니다.
- 웹 테스트 96 → 118개.

## 2026-10-15 — DB 이미지 교체: 공식 postgres 16 + PGDG PostGIS (보안판을 받을 수 있게)

과정·후보 비교·되돌리기는 [DB 이미지 교체](db-image-2026-10.md), 결정은 [ADR-007](adr/ADR-007-postgis-image.md).

  PostgreSQL 16.15 · PostGIS 3.6.4 · GEOS 3.14.1 · PROJ 9.8.1 · Debian 13(glibc 2.41), arm64 네이티브.
- 데이터 디렉터리는 그대로(같은 메이저). 전체 백업·볼륨 사본을 만든 뒤 교체했고, amcheck 로 btree 355개 확인, trigram GIN 1개는 다시 만듦.
  같은 데이터·코드로 계산을 교체 전후 두 번 돌려 지표·최근접·은행 지점 영향·도보 등 표 9개(736,765행)가 모두 같음.
- 경계 단순화(`ST_SimplifyPreserveTopology`)는 GEOS 수정으로 고르는 꼭짓점이 일부 달라짐(차이는 허용 오차 안, 잘못된 다각형은 없어짐).
  화면 지도는 저장된 단순화 경계를 써서 그대로이고 다음 `make sgis` 때 반영. 좌표 변환은 마지막 자리(최대 2나노미터)만 다름.
- `make db-update` — PostgreSQL 16 마이너·Debian·PostGIS 3.6 패치 보안판 받기(캐시 없이 다시 빌드 → db 재시작 → 확장 갱신).
- CI 의 PostGIS 를 공식 `postgis/postgis:16-3.5`(PG 16.9·Debian 11·`en_US.utf8`) 대신 같은 `db/Dockerfile`·`C.UTF-8` 로.
- db 컨테이너 `/dev/shm` 을 Docker 기본 64MB 에서 1GB 로(`shm_size: 1g`) — 병렬 해시 조인 한도(384MB, 계산 세션 768MB)보다 작아
  해시 표가 60MB 를 넘는 조인이 `could not resize shared memory segment` 로 실패했음. 지금 앱 쿼리는 최대 11MB, 쓰는 만큼만 차지하는 상한.

## 2026-10-15 — 2차 코드 리뷰: 수집 보호의 빈틈, 요청 밀반입, 재현성, 화면 상태

계획과 근거는 [improve/PLAN.md](improve/PLAN.md), 진행 기록은 [improve/PROGRESS.md](improve/PROGRESS.md), 결과는 [improve/REPORT.md](improve/REPORT.md).
- 리뷰 방식: 영역 8개를 리뷰 에이전트가 맡고, 지적마다 별도 에이전트가 반박을 시도했습니다. 그 결과 확인 41건·추정 4건이 남았습니다(반박 3건 제외).
- 버그는 모두 실패하는 테스트로 먼저 재현했고, 수정 전 실패 출력은 커밋 메시지에 있습니다.

**데이터 보호** ([ADR-023](adr/ADR-023-collector-data-guards.md) 보완)
- 도보 지표가 경계를 연도 없이 조인함 → 경계를 두 해 적재하면 도보 계산이 영구히 실패. 이제 그 해 경계만 조인합니다.
- 우체국: 가운데 쪽이 비거나 잘려도 성공 코드로 병합해, 받지 못한 시설을 '문 닫음'으로 처리했습니다. 이제 그런 코드는 미완료로 봅니다.
- KOSIS: 모든 시도가 '조회결과 없음'이면 그 해 고령인구를 지우고 DONE 이었습니다. 이제 지우지 않고 FAILED 입니다.
- SGIS: 일시 오류(토큰 발급 포함)에도 전국 경계를 직전 연도로 바꿨습니다. 이제 SGIS 가 '자료 없음'(0건·-100)으로 답했을 때만 대체합니다.
- 주소 검색의 일시 오류가 'ERROR' 로 영구 캐시되던 것 → 다시 조회합니다.
- 도보 재계산이 은행 지점 영향의 이전 도보 값·사유를 남기고, 계산 뒤 새 지점이 섞이던 것 → 열을 먼저 비우고 그 계산 실행의 지점만 씁니다.
- 금융 가능 판정 규칙을 바꿔도 원천이 같은 시설은 옛 판정이 남던 것 → 판정이 바뀐 시설도 이력을 닫고 새로 엽니다(지난 계산 실행의 재현성 유지).
- 은행 지점의 소속 지역에 경계 밖 최근접 붙이기가 없어 HIGH 지점이 보고서에서 빠지던 것 → 우체국과 같은 규칙을 씁니다.
- Ctrl-C 로 멈춘 계산·수집이 RUNNING 으로 남아 수 시간 같은 종류를 막던 것 → 17곳을 BaseException 으로 바꾸고 정적 검사를 뒀습니다
  ([ADR-025](adr/ADR-025-run-records-close-on-interrupt.md)).
- 기상청 수집이 멈추면 받은 격자를 버리던 것 → 받은 것은 저장한 뒤 멈춥니다.
- `make restore-undo` 가 되돌릴 DB 없이 지금 DB 이름부터 바꾸던 것 → 먼저 확인하고, 이름 교체는 한 트랜잭션으로 합니다.
- 대량 변경 멈춤·전수 미완료가 오류 로그·품질 ERROR 에 나타나지 않던 것 → 품질 규칙 `MASS_CHANGE_HELD` 를 두고, PARTIAL 에 사유를 남깁니다.

**데이터 손실 방지** ([ADR-023](adr/ADR-023-collector-data-guards.md))

  5%(최소 20곳) 넘게 닫히면 멈추고 품질 ERROR.
- 약국·병의원(빈·일부 응답에 전부 삭제), 은행 전수 수집(실패한 쪽이 있어도 완료), KOSIS(일부 시도 실패에도 그 해 전체 삭제),
  공휴일(빈 응답에 그 해 삭제) — 완전성 확인·상한·범위를 좁힌 삭제.
- `make restore` 가 검증 전에 DB 를 지우던 것 → 임시 DB 에 풀고 이름 교체(`make restore-undo`). 도보 재계산은 한 트랜잭션(실패 때 이전 결과 유지).

**보안** ([ADR-013](adr/ADR-013-api-security.md))
- `X-Forwarded-For` 위조로 속도 제한을 피할 수 있던 것 → 웹 프록시가 실제 주소로 덮어쓰고, API 는 신뢰 프록시를 오른쪽부터 건너뜀.
- 요청 본문 64KB 상한(413 `PAYLOAD_TOO_LARGE`), 지도·방문 여건 자유 입력 검증(비싼 계산·만료 없는 캐시 키 방지), 달력의 극단 날짜 400.
- 공개 실행 목록의 오류 원문(SQL·바인드 값) 마스킹, CSP 보고의 시간당 상한(Redis 가 없으면 닫힘), 지도 말풍선 이스케이프,
  퍼센트 인코딩한 `..` 경로 차단, API 컨테이너에 외부 키 원문을 넘기지 않음, 빌드 컨텍스트에서 `.env`·백업 제외.

**신뢰성**
