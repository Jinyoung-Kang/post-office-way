## 찾아서 고친 문제

| 문제 | 원인 | 조치 |
|---|---|---|
| `page=99999999999` 등에서 500 (4곳) | 정수 범위를 넘는 값이 DB 형 변환(`bigint`/`smallint`)에서 실패 | 매개변수 범위 검사(`page` 1~100,000, 시설 유형 0~9) + DB `DataError` → 400 `VALIDATION_ERROR` |
| 지역 순위가 같은 요청을 두 번 | 시도 목록이 늦게 와 기본 시도가 정해지면, 시군구 순위와 무관한데도 효과(effect)가 다시 돎 | 요청에 실제로 쓰는 값만 의존 |
| 데이터·운영이 품질 요약을 두 번 | 머리글 배지와 본문이 따로 요청 | 짧은 캐시(5초)로 같은 요청 합치기 |
| 오류 로그 한 건이 로그 창을 덮음 | DB 오류 문자열에 SQL 원문·바인드 값이 포함 | 한 줄 요약(SQL·바인드 값 제거 — 바인드 값은 사용자 입력일 수 있음), 자세한 내용은 traceId 로 서버 로그 |
| 제3자 스크립트를 평문으로 받음 | 카카오 SDK 가 페이지 프로토콜(http)을 따라 본체·타일을 받음 | CSP `upgrade-insecure-requests` + 외부 출처 `https://` 한정 |
| DB 장애 복구 때 워커 전체 재시작 | LISTEN 연결 오류가 차선 스레드를 끝냄 | 차선이 1·2·4…30초 간격으로 다시 연결 |
| 데이터·운영 레이아웃 이동 (CLS 0.194) | 오류 로그 자리 표시(96px)와 실제 목록(최대 360px) 높이 차이 | 로그 창을 고정 높이로 — 불러오는 중·없음·있음 모두 같은 높이 |
| 한눈에 레이아웃 이동 (CLS 0.088) | 방문 여건 배너가 예보를 받은 뒤 숫자 위에 끼어듦 | 배너 자리를 먼저 잡아 둠 |
| 첫 화면 제목이 0.5초 늦게 보임 | 제목 애니메이션이 투명도 0 에서 시작 → 브라우저가 LCP 후보에서 빼 데이터 뒤의 작은 글자가 LCP | 투명도 없이 움직임만 |
| 지도 화면 멈칫함 | 시군구 252곳 폴리곤(좌표 수만 개)을 한 번에 만들어 0.5초 넘는 긴 작업 | 약 12ms 조각으로 나눠 만들고 사이에 브라우저에 양보 |
| 지도 첫 그림이 늦음 | 지도 컴포넌트가 하이드레이션 뒤에 SDK 를 받기 시작 | 지도 화면이 그려지는 즉시 SDK 받기 + SDK 출처 preconnect (지도 없는 화면에서는 받지 않음 — 확인) |
| 입력 칸 이름 없음 (Chrome 이슈) | `select`·`input` 에 `id`/`name` 없음 | `name` 지정 |
| 방문 여건 출처 `에어코리아 발표 —` | 미세먼지 예보는 모레까지만 발표 | "아직 이 날짜까지 발표되지 않음" |
| **(10-08) 모든 지도가 빔** | 카카오 SDK 가 본체를 `t1.daumcdn.net` → `t1.kakaocdn.net` 에서 받도록 바뀌어 CSP 에 막힘. 서버 기록이 없어 화면을 열어야 알 수 있었음 | 새 호스트 허용(스크립트는 와일드카드 없이) + **CSP 위반 보고 수집** → 오류 로그 '보안 정책' |
| (10-08) 은행 지점 '잃는 주민'이 516만 명 | 이미 2km 밖에 살던 주민까지 셈 | '지금은 2km 안인데 닫히면 2km 밖'만 → 77만 명 (도보도 같은 정의) |
| (10-08) CSP 보고 엔드포인트 500 | 보고 값에 숫자가 오면 문자열 처리에서 실패(퍼징) | 모든 값을 문자열로, 지시어 없는 보고는 버림 |
| (10-08) 도보 작업 뒤 워커 메모리 1.16GB | 파이썬이 쓴 메모리를 OS 에 돌려주지 않음 | 무거운 작업은 spawn 자식 프로세스 → 69MB |
| (10-08) 은행 지점 목록 배지 대비 · 보고서 표 스크롤 | 고른 행 배경 때문에 배지 대비 4.5:1 미만 · 스크롤 영역에 키보드 초점 없음 | 왼쪽 파란 막대로 표시 · `tabIndex`·`role="region"` |
| (10-08) 지표 계산 80초 중 순위 20초 | 같은 트랜잭션에서 넣은 10만 행이 통계에 없어 UPDATE 가 나쁜 계획 (따로 돌리면 1.8초) | 큰 삽입 뒤 `ANALYZE`, 은행 지점 영향은 INSERT 한 번에 → 계산 40초 |
| (10-08) 모바일에서 페이지 전체가 축소됨 (생활 거점 630px · 데이터·운영 481px · 방문 여건 477px · 은행 지점 641px) | 표 안 `sr-only` 글자가 스크롤 상자 밖으로 샘 · 한 열 그리드가 표 폭으로 늘어남 · 세그먼트 버튼 줄바꿈 없음. 점검은 모바일 화면 축소로 `innerWidth` 가 같이 커져 0 으로 보였음 | `.tbl` relative · `grid-cols-1` · `.seg` 가로 스크롤, 점검은 375px 와 비교 |
| (10-08) Tailwind 4 전환 직후 메뉴·배지가 링크 색 | v4 는 cascade layer — 레이어 밖 `a { color }` 가 명시도와 상관없이 컴포넌트·유틸리티를 이김 | 요소 기본 스타일을 `@layer base` 로 (전후 26장 픽셀 비교로 확인) |
| (10-08) 테스트가 못 돎 | 저장소의 빈 파일 18개 권한이 600 으로 바뀌어 비루트 컨테이너가 못 읽음 | 644 로 (git 기록 권한과 같게) |

고정 카드, 등급 버튼 글자 수, 선택 상자 폭, 한 열 그리드가 표 폭으로 늘어남)을 차례로 고쳐 0.001. 지도·방문 여건은 09-26(91·92)보다
조금 낮은데, 같은 컴퓨터에서 다른 도커 스택이 함께 돌고 있었고 Lighthouse 의 CPU 감속은 실제 CPU 시간을 바탕으로 하므로 그 영향일 수
있습니다(추정 — 원인은 따로 확인하지 않음).

- 지도가 있는 화면(지도·방문 여건)의 성능 점수는 카카오 SDK 자체의 스크립트 실행과 폴리곤 수에 좌우됩니다.
  지도 화면의 **모범 사례 93~96** 은 로컬이 http 라는 점과 카카오 SDK 가 시도하는 `eval` 을 CSP 로 막은 기록 때문이며,
  `'unsafe-eval'` 을 허용하지 않는 쪽을 택했습니다([ADR-013](adr/ADR-013-api-security.md)).
- 측정은 같은 컴퓨터에서 다른 도커 스택이 함께 도는 상태라 실행마다 ±5점 정도 차이가 있어 3회 중앙값을 적었습니다.
